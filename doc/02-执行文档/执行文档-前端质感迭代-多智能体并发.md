## 0. 这份文档是什么 / 不是什么

**是**：一次以"高级质感的独立开源商业产品"为目标的前端视觉与交互打磨的执行计划——设计方向、现状审计结论、并发执行模型（文件所有权矩阵、各子智能体任务书、同步点）、验收标准与止损条件。

**不是**：像素级视觉稿（以现网真实渲染 + 浏览器走查为准）；后端契约变更（API、状态机、路由一律不动）；新功能需求（只做质感与状态完备性，不做 inbox / autopilot 等立项外功能）。

**与 `执行文档-前端-web.md` 的关系**：那份文档管"做什么功能、消费什么契约"；本文档管"做到什么质感、怎么并发地做"。两者冲突时：字段 / 路由 / 闭环以后者为准，视觉 / 密度 / 交互细节以本文档为准。

## 1. 设计方向（Design Read）

**一句话判读**：面向开发者与独立创作者的 Git 原生工单看板产品 UI，克制、精密的开发工具气质，Primer 式冷中性表面 + 单一青色信号色，边框与间距承担分组，阴影只用于真实抬升（弹层）。

**刻度**：`DESIGN_VARIANCE 6 / MOTION_INTENSITY 4 / VISUAL_DENSITY 7`。
看板是高密度产品 UI，不是营销页；落地规则只取产品 UI 适用子集（颜色锁、形状锁、状态完备、可达性、AI-tell 清除），营销页套路（hero、marquee、bento、滚动劫持）一律不适用。

**调研吸收**（已完成，不再重复调研）：

| 来源 | 吸收什么 | 不抄什么 |
|---|---|---|
| GitHub Projects / Primer | 信息密度、状态徽标的克制表达、边框分组、mono 数字 | GitHub 蓝色字面量、营销页 |
| Planka | 看板卡片流转的轻量动效与拖拽反馈 | 圆角卡片墙、彩色标签泛滥 |
| Plane | 工作项视图组织、属性面板层级 | 多视图切换复杂度 |
| Dub / Outline | 克制的产品质感、单一信号色、留白节奏 | 首页营销叙事 |

## 3. "高级质感"的可验收定义

以下每条都是验收项，不是形容词：

1. **token 唯一**：视图与组件 scoped 样式中零硬编码色值（`rgba(...)` 仅允许由语义色衍生的已有 token，如 `--accent-soft`）；发现缺 token → 报告给基座，不私造。
2. **单一信号色**：全站交互强调只用 `--accent` 族；语义色只表达真实状态（success/warning/danger），不做装饰。
3. **形状锁**：圆角只用 `--radius-sm/md/lg`（8/10/14），`--radius-xl` 仅弹层；同一控件族圆角一致。
4. **密度 7**：分组优先用边框 + 间距 + 对齐，卡片容器只在该有层级的地方出现；数字 / hash / token 计量一律 `--font-mono`。
5. **动效 ≤ 150ms**：只动 `transform` / `opacity`；全局 reduced-motion 已兜底，不新增绕过。
6. **状态完备**：每个数据视图有骨架屏（形状匹配最终布局）、空态（说明如何产生数据）、错误态（inline 或上下文提示，不滥用 toast）。
7. **可达性**：双主题下文字对比 WCAG AA（正文 4.5:1）；焦点环走全局 `:focus-visible`；键盘路径不回退（⌘K 面板、Esc、Tab 陷阱保持）。
8. **文案语域**：界面中文短句、功能式表述；**零 em-dash（—）**；占位符不当标签用。
9. **响应式**：沿用既有 860px / 560px 两档折叠模式，逐视图显式声明，不靠"应该没问题"。
10. **行为零回归**：路由名、API 调用、store、类型、事件语义一律不动。

## 4. 并发执行模型

### 4.1 波次与依赖

```
Wave 0  调研 + 审计（已完成，即本文档 §1/§2）
Wave 1  Agent A 基座先行（token / G* 组件 / 壳层 / 样式速览）——必须最先合入，
        因为 Wave 2 三个智能体消费它产出的 token 契约
Wave 2  Agent B ∥ Agent C ∥ Agent D 三路并发（文件集互斥，见 §2.4）
Wave 3  Agent E 验证（typecheck / build / vitest），机械性修复并逐条留痕
Wave 4  主智能体浏览器走查（browser-use 限主智能体）：双主题截图、交互冒烟、
        出具打磨清单；小修回派给对应归属或主智能体自行处理
```

调度原则：Wave 1 未合入前 Wave 2 不开工（契约依赖）；Wave 2 三路无相互依赖，失败一路不影响其余两路合入。

### 4.2 全员红线（每个子智能体任务书内嵌同一份）

1. 只写自己名下的文件（§2.4 矩阵）；读不限。
2. 不动：`src/api/`、`src/stores/`、`src/router/`、`src/types/`、`src/composables/`、`package.json`、后端任何模块。
3. 不新增依赖；图标只用既有 `GIcon` 体系。
4. token 只消费不私造；缺 token 写进完工报告，由 Agent A 统一补。
5. 保持：中文界面文案、aria / 键盘行为、双主题、reduced-motion、860/560 断点模式。
6. 界面字符串零 em-dash；不引入新英文眉题 / 装饰性小标签 / 装饰性彩点（真实语义状态点除外）。
7. 完工报告必须包含：改动文件清单、销号的缺陷编号（D1-D5 及自查项）、遗留问题。

### 4.3 各子智能体任务书

#### Agent A — 基座（Wave 1，串行独占）

- **文件**：`styles/global.css`、`components/ui/*.vue`、`views/AppLayout.vue`、`views/StyleGuideView.vue`。
- **任务**：
  1. 销号 D1：AppLayout 全部 GitHub 字面量迁到 `--sidebar-*` / `--accent-*` token（激活态用 `--sidebar-active` + `--sidebar-active-border`，图标高亮用 `--sidebar-accent`，次级文字用 `--sidebar-muted`，命令面板选中用 `--accent-soft` + `--accent-border`）；scoped 样式里的 fallback 字面量（`#1f2328` 等）一并清除。
  2. 销号 D2：移除 `GATE / WORKSPACE` 眉题；页面上下文改由标题 + 既有 `closedLoop` 徽标承担；topbar 维持 ≤ 64px 单行。
  3. 逐个审计 9 个 `G*` 组件：硬编码色清零、圆角入阶梯、hover/active/focus/disabled 全态、AA 对比度；`GButton` 主次层级与 `:active` 物理反馈（translateY 1px）确认。
  4. `global.css`：token 只增不改名；按 Wave 2 报告统一补缺（本波先补可预见的：骨架屏 token `--skeleton` / `--skeleton-strong` 若不存在则新增）；阴影保持"弹层专用"。
  5. `StyleGuideView.vue` 同步为 token 与组件现状的活文档（色板 / 圆角 / 字阶 / 组件态）。
- **验收**：§3 全部十条在基座范围成立；`npm run typecheck` 通过。

#### Agent B — 看板面（Wave 2）

- **文件**：`views/TicketKanbanView.vue`、`views/HomeView.vue`。
- **任务**：token 迁移与硬编码清理（销号 D3）；看板列头信息降噪（列 = `TicketStage`，计数 mono，克制表达优先级与异常）；卡片密度与可读性打磨（标题 / 编号 / 责任人 / 成本字段的层级与截断规则）；拖拽反馈动效 ≤ 150ms 且只动 transform/opacity；骨架屏按列形状设计；空看板引导态；860/560 折叠显式声明；HomeView 与 Kanban 视觉语言统一但布局家族不雷同。
- **验收**：§3 十条 + 完工报告。

#### Agent C — 工作面（Wave 2）

- **文件**：`views/TicketDetailView.vue`、`views/SessionView.vue`、`views/ReviewConsoleView.vue`。
- **任务**：token 迁移（销号 D3）；审核台保持 P1 重心投入：tree_hash / base_commit 显式 mono 展示（P3 原则）；Decision 展示的状态语义色只走语义 token；会话视图消息流的密度与等宽块（diff/hash）排版；SSE 断连 / 重连 / 结束三态可视；三个视图的加载 / 空 / 错误态（销号 D4）；长内容滚动容器不产生整页滚动。
- **验收**：§3 十条 + 完工报告。

#### Agent D — 控制台面（Wave 2）

- **文件**：`views/LoginView.vue`、`views/AgentConfigView.vue`、`views/SystemSettingsView.vue`、`views/CostPanelView.vue`。
- **任务**：token 迁移（销号 D3）；LoginView 是产品门面：单一信号色、表单标签在输入框上方、焦点环与错误文案 AA 对比、无营销废话；表单类视图（AgentConfig / SystemSettings）控件对齐与分组边框化；CostPanel 数字全部 mono、表格密度 7 档、指标层级（总量 → 工单 → 会话）清晰；四视图状态完备（销号 D4）。
- **验收**：§3 十条 + 完工报告。

#### Agent E — 验证（Wave 3）

- **文件**：无所有权；仅允许修复 typecheck / build / test 暴露的机械性错误（拼写、未用变量、类型标注），逐文件留痕并通报归属智能体。
- **任务**：`npm run typecheck` → `npm run build`（产物落入 gate-web static）→ `npm run test`；输出三段结果与修复清单。
- **验收**：三项全绿 + 留痕完整。

#### 主智能体 — 视觉终审（Wave 4，browser-use 限主智能体本人执行）

- 启动 dev（MSW mock 兜底），双主题逐路由走查：导航 / ⌘K / 看板拖拽 / 审核台 / 会话 SSE / 设置分区；截图留档；对照 §3 出打磨清单并小修收口。

### 4.4 失败与止损

- 任一子智能体受阻（文件冲突、契约缺口、mock 数据不足）：停在其文件集内，完工报告写明，不越界自救。
- Wave 2 全部失败 ≥ 2 路：回退到串行模式，按 B → C → D 逐个重派。
- Wave 4 发现系统性问题（如 token 体系本身要推翻）：停止打磨，升级为设计复盘，不在视图层打补丁。
- 总止损线：任何时刻 `git status` 里不得出现所有权矩阵之外的文件改动。
